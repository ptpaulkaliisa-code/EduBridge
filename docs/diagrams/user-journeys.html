How a parent and a school actually use EduBridge

There is no app to download. EduBridge is a website a parent opens from a link on any phone browser, and SMS does the rest. Below is every step from first contact to daily use, marked by what the code does today.

Works Partial or needs setup Not built / blocks the journey

A parent cannot get in today

When an admin adds a student, the parent's phone number is saved on the student record only. No parent account is ever created and the student is never linked to one. So at step 3 a parent gets “Account not found — contact your school admin”, and even if one got through, their dashboard would show no children. Separately, every alert SMS is queued but nothing sends the queue.

To make Journey A work end to end

Three changes, in this order

  1. FIRST

    Create and link parent accounts

    When a student is saved with a parent phone, find or create a parent user for that number and set parent_id. One parent, many children, matched by phone. Without this nobody gets past login.

  2. SECOND

    Send the SMS queue

    Implement process-sms to send pending rows through Africa's Talking, mark them sent or failed, and add the cron schedule to vercel.json. This is the feature parents notice most.

  3. THIRD

    Welcome SMS with the link

    When a parent account is created, text them the web address and how to log in. That replaces the “download” moment and removes step 2's manual handoff.
